# Бэклог после планов 1 и 2

Замечания ревью, отложенные при реализации плана 1 (ядро + CLI) и плана 2 (приложение).
Исправленные в финальных волнах сюда не входят. Пути и строки плана 1 — на коммите
`4d7f07f`/`b024e52`, плана 2 — после финальной волны ветки `feat/tauri-app`; могли сдвинуться.

## До публичного релиза

- **Лаунчер принимает копию плейсета?** Ручная проверка spec §6: `sort --apply` на копии базы →
  запуск лаунчера → новый плейсет виден и запускается. Если не виден — копировать `pdxUserId`
  (и `offDisk`, `lastUsedAt`) из исходной строки (`apply.rs`); имя копии ≤ 128 символов.
- **Свежая калибровка.** Запустить игру с плейсетом и `ck3h calibrate`: подтвердить R27 (порядок
  чтения с учётом регистра) и разобрать 3 строки «одно определение» и 72 «предсказано, не в логе».
- Перепроверить порядок чтения и пути по умолчанию на Windows и Linux.

## До плана 2 (Tauri)

- **Производительность и память — решает владелец.** Сделано (план 2, задача 3): пути, база и
  язык — общие `Arc` на весь индекс; транзитивные зависимости — одно `DepClosure` на анализ;
  определения группируются, потом сортируется каждая группа. Отчёты совпадают байт в байт (`cmp`
  всех четырёх JSON). Цель Q25 — пик `conflicts --game` не больше половины эталона — **не
  достигнута**. Плейсет владельца, release, `/usr/bin/time -l`, 2026-11-18:

  | Прогон | Пик RSS до | Пик RSS после | Время до | Время после |
  |---|---|---|---|---|
  | `conflicts --json` (без ванили) | 320 МБ | 329 МБ | 3,33 с | 2,31 с |
  | `conflicts --game … --json` | 327 МБ | 322 МБ | 12,46 с | 5,47 с |
  | `sort --game … --json` | 326 МБ | 344 МБ | 7,99 с | 3,28 с |
  | `calibrate --json` (ваниль из Steam) | 347 МБ | 453 МБ | 9,57 с | 1,80 с |

  Таблица мало что говорит: пик RSS одного и того же бинарника скачет на ±100 МБ от запуска к
  запуску, а эталон снят с холодным кэшем диска. Три чередующихся прогона с тёплым кэшем (медианы
  RSS до → после): 373 → 353, 402 → 356, 440 → 380, 430 → 399 МБ; время почти не изменилось —
  его съедают чтение и разбор файлов. Точнее — счётчик кучи в `conflicts --game`: хранимый индекс
  модов 71 → 32 МБ, модов с ванилью 258 → 135 МБ (−48 %), а пик 421 → 402 МБ (в один поток
  340 → 260 МБ). Пик набирается при индексации модов: разбор одного файла временно берёт около
  230 МБ сверх индекса, а параллельная индексация (rayon) складывает такие всплески. Что именно
  (лента jomini, копия текста в `decode`) и какой файл — не проверялось. Дальше — менять разбор или
  ограничить параллельность. Приложение, которое держит анализ в памяти, после загрузки хранит
  135 МБ вместо 258.

## После плана 2 — отложенные замечания ревью

### Задача 18 (CI и релизы)

- **Тесты обновлений без сети (#12).** `fetch_latest` не покрыт тестами
  (`app/src-tauri/src/update.rs:49`), а тесты проверки обновлений пошли бы в api.github.com, если
  сломается защита «нет `repository`». В том же коммите, что задаёт `repository`, — подменяемый
  загрузчик в `check_update_with`.
- **Prettier не проверяется (#19).** `npm run format` переформатирует чужие файлы; в шаг линтера
  CI — `prettier --check .` (`app/package.json`).
- **`tauri build` переписывал `app/src-tauri/Cargo.toml` (#37).** В финальной волне закоммичена
  форма, которую пишет tauri-cli (`{ version = "2", features = [] }` у `tauri` и `tauri-build`);
  повторная сборка дерево не меняет. В CI релиза проверить то же самое.

### Задача 19 (ручная проверка)

- **Доступ к папке «Документы» на macOS не проверен (M5).** База лаунчера лежит в
  `~/Documents/Paradox Interactive/…`; при отказе пользователь видит «База Paradox Launcher не
  найдена», а с ad-hoc подписью вопрос может повторяться после обновления. Если запрос есть —
  `NSDocumentsFolderUsageDescription` через `app/src-tauri/Info.plist` и строка в README на двух
  языках («разрешите доступ к папке Документы»).

  показывает текст победителя: `loc_value` ищет по паре файл + ключ

- `ConflictsOutput` повторяет поля `ConflictReport` вручную — лучше исчерпывающая деструктуризация

- Ваниль держит по одному `Arc` языка и базы на слой DLC, а не на индекс (`index.rs:194`) —
  несколько КБ (#6).
- Путь лога в ошибке CLI на Windows — со смешанными разделителями (`session.rs:86`); файл всё
  равно открывается (#7).
- Тесты: нет теста CLI на `error: log not found:` и на текст нечитаемого лога
  (`crates/ck3h-cli/tests/cli.rs`) (#4, #8); нет теста на общий `Arc` пути и базы

### Rust-часть приложения

- **Удаление правила по номеру (M2).** Если `rules.toml` правили снаружи, пока список открыт,
  удаляется правило, которое теперь стоит под этим номером, вместе с заметкой
  (`app/src-tauri/src/rules_file.rs:22`, `app/src/components/RulesEditor.tsx:156`). Передавать
  `before`/`after` вместе с номером и отказывать при несовпадении — или перечитывать список при
  открытии подтверждения.
- Правила, записанные строкой-массивом `rule = [ {...} ]`, читаются, но не правятся: правка
  отвечает «Файл правил не читается» (`rules_file.rs:57`). Приложение и документация так не пишут,
  файл не трогается (#10).
- Ошибка записи настроек и ошибка разбора правил при правке не называют файл
  (`app/src-tauri/src/state.rs:103`, `rules_file.rs:46`, `:51`) (#13).
- Без `dirs::config_dir()` папка настроек — относительная `ck3-helper`
  (`app/src-tauri/src/lib.rs:20`); на трёх целевых системах не бывает (#14).
- `mod_warnings` с неизвестным id отдаёт пустой список (`state.rs:236`); интерфейс передаёт только
  id текущего анализа (#9).
- Подмена анализа без счётчика поколений (`state.rs:144`); анализы разводит интерфейс (R15), а
  сохранение настроек во время анализа недоступно (#15).
- `updateCheckedAt` из будущего (сбитые часы) отключает проверку обновлений до этого времени

- `settings.toml`, исправленный руками при открытом приложении, следующее сохранение из
  приложения перезапишет без `.bak` (`app/src-tauri/src/settings.rs:73`) (#17).
- Тесты: предложение порядка с ванилью, `LauncherStatus::Unknown`, содержимое `unresolved_rules`

## Движок и калибровка

- `Mismatch` не отличает ошибку порядка от устаревшего лога; путь из лога в нижнем регистре;
  нет имени мода-прогноза (`calibrate.rs`).
- Проверка «последнего запуска»: относительные пути в `.mod`, порядок модов не сравнивается,
  отсутствие `dlc_load.json` ничего не печатает.
- R16: перемещение мода выше мода с `replace_path` убирает файлы без сигнала.
- Правила сопоставляются со всеми модами, зависимости — только с включёнными; у
  `unresolved_rules` нет причины. Дубли правил дают дубли причин.
- Ошибки разбора `descriptor.mod` теряются на пути R12 и у выключенных модов.
- Значение локализации захватывает хвостовой комментарий с кавычками (`index.rs:379`).
- Предупреждения файлов, заменённых слоем DLC, остаются в индексе ванили.
- I/O-ошибки индекса и бэкапа не называют файл.
- Строка `playsets_mods` без записи в `mods` даёт вечный `OrderMismatch`.
